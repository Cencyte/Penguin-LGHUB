# From individual blockers to a usable map

An assistant's retrospective for Cencyte, at the transition back to composition
implementation on October 11, 2026.

Penguin-GHUB began with the practical problem of Logitech functionality on Linux:
device configuration, G-Shift and the possibility of a native replacement. The
September 2 repository scaffold was followed by hardware and protocol work,
including the discovery that G-Shift data was stored onboard. The priority then
became getting the original G HUB software to work through Wine. This mattered
for Cencyte's music-production workstation as well as gaming peripherals.

The dated repository records span 39 elapsed calendar days, September 2 to
October 11. Wine-specific work is recorded from September 22, a 19-day span;
DragonShard-2 tooling appears on October 3, eight days before this checkpoint.
Those are calendar intervals, not measured active labor or uninterrupted compute
time. We do not have a reliable total for either of those, or for the credits
spent across subscriptions and predecessor sessions.

The Wine work crossed several layers: installer directory sharing, device
identities, wait packets and messaging, WinRT factories, shared resources,
composition and input sites. Some application UI had already appeared for
Cencyte. That observation was compatible with the continuing failures in the
separate native tray path; describing the whole application as unable to start
would have obscured that distinction.

The initial approach made local advances but gave a poor account of the remaining
territory. One missing API could expose another without telling us how many
dependencies lay behind it. Cencyte pushed for a different toolchain: preserve
the original DragonShard idea, build an upgraded version, consult SystemSage,
and use the workstation for a broad decompilation campaign before resuming
implementation. That was a substantive correction to the working method.

The eventual corpus comprised 21 selected binaries and 600,281 identified
functions. Independent headless Ghidra processes, private databases, deterministic
shards and persistent indexes made that scale manageable. The obstacles were
not just instruction decoding: shared database serialization, slow NTFS-backed
working storage, save bottlenecks, interrupted jobs, stale checkpoints, disk
pressure and changing RAM availability all affected useful throughput. Working
analysis moved to ZFS while Captures retained durable evidence. Recovery and
reconciliation mattered as much as launching more workers.

Every identified function now has an export/index record. The eleven ordinary
C-export exceptions have supplemental recovery. All five failed tracing cases
were recovered. Of 427 reported high-level gaps, 316 were processor traps, 103
received matching high-level transfers and eight received instruction-level
explanations. Across the wider corpus, 74 non-trap sites still lack high-level
slices. Static dispatch classification covers 116,290 recorded sites, but it
does not magically reveal every runtime object or callback.

The payoff is a more precise implementation decision. Two headless tray traces
showed the same target failing LINEAR interpolation setup, returning with both
overlay contexts null, and subsequently dereferencing a null overlay. A further
trace bound the call to our actual compositor method. Another run stopped on
the separate GL/shared-texture failure. These are preserved observations, not
guesses inferred from an idle window or a successful process launch.

Working with Cencyte means treating resource use, provenance and visibility of
progress as part of the engineering task. His repeated challenges about idle
cores and unmoving percentages exposed weaknesses in both scheduling and our
explanations. CPU utilization is still not a completion metric, and serial work
cannot always use 48 threads; the obligation is to demonstrate why a bottleneck
exists and put independent useful work alongside it when possible. Vague
reassurance did not meet that obligation.

The dragons and Mana gave the work a shared vocabulary. The lasting result is
more practical: a retrievable map, reproducible probes, retained failures and a
clearer boundary between exported evidence and functioning software. Cencyte has
now accepted the analysis phase as cleared. We return to composition with a
confirmed failure chain and concrete tests, while keeping the remaining research
backlog visible. The corpus is finished as an export; G HUB compatibility is not.
